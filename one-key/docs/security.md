# V0.1 安全设计

## 保护目标

V0.1 主要保护离线复制、设备备份泄露和普通文件浏览场景下的 Vault 内容。账户名称、URL、用户名、密码、标签、自定义字段和备注均进入加密 Payload。

## 文件格式

`vault.localvault` 是 JSON Envelope，明文 Header 仅包含：

- Magic 与格式版本
- PBKDF2-HMAC-SHA256 参数和随机 Salt
- AES-256-GCM 标识和随机 Nonce
- Base64 编码的认证密文（GCM Tag 包含在内）

Header 的固定安全参数作为 AES-GCM AAD。读取时参数必须与受支持的 V1 参数完全一致，避免攻击者把 KDF 参数改成异常值造成资源耗尽。

## 密钥生命周期

主密码只作为创建/解锁调用参数存在，不写入文件、Store 或日志。系统 `PBKDF2WithHmacSHA256` 派生出 256 位 Key；密码字符数组与 Key 在可控生命周期结束时覆盖。Kotlin/Java `String` 不可可靠原地清除，这是 Android 托管运行时的已知限制。

解锁后的 JSON 与 Key 只保留在原生插件进程内存。手动锁定、超时锁定、后台锁定或进程退出后，不再可通过页面读取。

## 参数

- PBKDF2-HMAC-SHA256
- 600,000 次迭代
- 128-bit 随机 Salt
- AES-256-GCM，96-bit 随机 Nonce，128-bit Tag

这些参数是首版兼容协议的一部分。后续调整必须引入格式迁移，而不是静默改变。

## 剪贴板

密码复制后记录 SHA-256 指纹。定时清理时只有当前剪贴板内容仍匹配该指纹才会清空，避免覆盖用户后来复制的其他内容。用户名与普通自定义字段使用系统普通复制，不进入密码定时清理流程。

## 网络与日志

Manifest 不声明 `INTERNET` 权限，统计关闭。生产代码禁止记录主密码、Vault Key、账户对象、密码、备注或秘密字段。

## 明确不保护

- Root / 系统已完全失陷
- 键盘记录、恶意输入法和高权限恶意软件
- 屏幕录制、肩窥与用户主动复制泄露
- 弱主密码的离线猜测风险
- 丢失且没有备份的本地 Passkey（完整 Passkey 尚未实现）
