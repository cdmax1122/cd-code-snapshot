# 通用拓扑图渲染引擎 \- 产品需求文档 \(PRD\)

## 1\. 项目概述

本项目旨在开发一个通用的拓扑图渲染引擎。MVP 阶段的核心逻辑为**纯数据驱动视图**：引擎通过解析模拟的静态 JSON 数据，映射并渲染出设备节点、连线及其拓扑关系，最终以“光储一体化电站”的真实业务场景作为唯一验收载体。



## 2\. 目标与边界

### 2\.1 核心目标

构建一个具备基础拓扑展示、多种连线动效、双轨布局能力的轻量级图形引擎底座。

### 2\.2 边界约束（不做什么）

- **纯展示性质**：不提供任何画布上的节点拖拽、连线绘制等可视化编辑功能。

- **静态数据源**：不对接真实后端接口，数据来源仅为前端本地模拟的 JSON。

    

## 3\. 核心功能需求



### 3\.1 节点渲染与展示

- **图元载体**：节点在画布上的默认包围盒为矩形，其视觉内容必须支持直接加载并展示外部 SVG 或图片格式（如 PNG/JPG）。

- **数据绑定**：节点的位置、展示图标、文本标签需完全由输入数据决定。

    

### 3\.2 连线渲染与动效

- **锚点规则**：连线与节点的连接点，必须固定在节点矩形包围盒的特定锚点上，当前需支持的锚点位置为：上边中点、下边中点、左边中点、右边中点。

- **动效能力**：连线需支持以下三种视觉流动效果（可配置）：

    1. **虚线偏移**：沿路径方向移动的虚线效果。

    2. **粒子流**：沿路径移动的光点/粒子效果。

    3. **纹理图案**：沿路径平铺并流动的纹理效果。

- **动态映射规则**：连线的流动效果必须具备方向性（正向/反向），且**流速必须与数据中给定的数值大小成正比**（数值越大，流动越快）。

    

### 3\.3 布局系统

系统需支持以下两种布局模式，按优先级依次处理：

1. **绝对定位**：当数据中包含明确的坐标信息时，节点必须严格按指定坐标落位。

2. **自动布局**：当数据中缺失坐标信息时，引擎需根据节点与节点之间的连线关系，自动计算并排列出合理的拓扑层级结构。

    

### 3\.4 画布视口与适配

- **居中适配**：在拓扑图初始化或数据变更后，引擎必须自动计算所有图元整体的包围盒，并通过缩放和平移变换，使整张拓扑图**默认居中且完整适配**当前画布的可视区域大小。

    

### 3\.5 交互约束与悬浮提示

- **信息交互**：当用户将鼠标悬停在节点上时，需展示该节点的基础详情信息（表现形式不限，如浮层或 Tooltip）。

- **交互限制**：严禁响应用户对节点或连线的点击、拖拽、框选等改变拓扑结构的操作行为。

## 4\. 验收标准 \(AC\) 与业务场景用例



本 MVP 的验收将采用\*\*“光储一体化电站真实微观拓扑”\*\*作为唯一标准测试场景。该场景包含 6 个核心节点、5 条物理连线，具备分支与能量潮汐反转，用于充分验证引擎的布局与动效能力。



### 4\.1 验收场景静态拓扑定义

不论处于何种天气模式，画布上的物理连接关系（无向图）必须保持如下结构：

- **光伏阵列** ──连线──\> **光伏逆变器**

- **光伏逆变器** ──连线──\> **交流母线**

- **交流母线** ──连线──\> **储能变流器 \(PCS\)**

- **储能变流器 \(PCS\)** ──连线──\> **电池簇**

- **交流母线** ──连线──\> **用电负载**

    

*\(注：引擎需通过“自动布局”或“绝对坐标”正确处理这种存在“交流母线”作为多分支节点的拓扑结构，连线需准确连接到节点对应的锚点上。\)*



### 4\.2 场景用例 A：晴天模式（光伏发电充储供电）

**业务逻辑**：光照充足，光伏发电，一部分满足负载，剩余部分通过 PCS 充入电池。

**预期表现验收点**：

1. **状态表现**：光伏、逆变器、PCS、电池、负载均呈现“运行/发电/充电”等激活态视觉样式。

2. **正向流动验证**：

    - `光伏 -> 逆变器` 连线：流光开启，方向正向，**高流速**（映射高功率）。

    - `逆变器 -> 交流母线` 连线：流光开启，方向正向，**高流速**。

    - `交流母线 -> 负载` 连线：流光开启，方向正向，**中流速**（映射负载功率）。

3. **充电分支验证**：

    - `交流母线 -> PCS` 连线：流光开启，方向正向，**低流速**（映射剩余充电功率）。

    - `PCS -> 电池簇` 连线：流光开启，方向正向，**低流速**。

        

### 4\.3 场景用例 B：雨天模式（电池放电保电）

**业务逻辑**：无光照，光伏停机，电池簇放电，经 PCS 逆变升压后通过交流母线供给负载。

**预期表现验收点**：

1. **状态表现**：光伏、逆变器呈现“离线/待机”视觉样式（如置灰）；电池呈现“放电”样式；负载保持“在线”。

2. **断流验证**：

    - `光伏 -> 逆变器` 及 `逆变器 -> 交流母线` 连线：**流光必须完全停止**（验证 isActive: false 的控制）。

3. **反向流动验证（核心难点）**：

    - `电池簇 -> PCS` 连线：流光开启，**方向必须反转为从电池指向 PCS**，**高流速**。

    - `PCS -> 交流母线` 连线：流光开启，**方向必须反转为从 PCS 指向交流母线**，**高流速**。

4. **常态分支验证**：

    - `交流母线 -> 负载` 连线：流光开启，方向保持正向（母线到负载），**中流速**。

        

### 4\.4 交互与适配验收（贯穿 A/B 场景）

1. **视口自适应**：在切换 A/B 场景导致节点状态变化（但不改变位置）时，或者首次加载包含 6 个节点的数据时，画布必须自动缩放平移，使上述完整拓扑结构居中且完整可见。

2. **悬浮交互**：在 A/B 任意场景下，鼠标悬浮至“交流母线”节点时，必须出现浮层提示（验证多分支节点的点击热区/包围盒计算准确）。

3. **零编辑响应**：在 A/B 场景下，尝试鼠标拖拽“电池簇”节点，节点位置不得发生任何偏移。
